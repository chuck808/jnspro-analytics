# Coaching

---

## What this actually is

A structured, consent-gated link between a coach and a rider — not a login share, not a data export. Once a coach and rider are linked, the coach gets a narrow, view-only window into that rider's onboarding profile and training goals, a shared message thread, and whatever session reports the rider chooses to push across. Nothing is pulled automatically, nothing is editable by the coach, and private session notes never travel with a shared report.

---

## Becoming a coach

Anyone can *use* AppGatePro as a rider, but coaching someone else's data — especially a minor's — needs vetting first. Before you can invite a single rider, an admin has to approve you. There are two ways in:

**At sign-up**, tick the optional box and fill in your club and coaching qualifications:

![Coach application checkbox at sign-up, with club and qualification fields revealed](/docs/coaching-signup-apply.png)

**Already have an account?** Do the same thing from Settings, under "Become a Coach":

![The Become a Coach form in Settings, with club pre-filled from your profile](/docs/coaching-settings-apply-form.png)

Either way, the same two fields matter: **club/team** and **coaching qualifications / safeguarding certification** — DBS certificate number, governing body membership, whatever you've got. There's no automated verification service behind this; a real admin reads what you wrote and makes a judgement call, same as they would for a paper application.

While it's under review, the Coach section of the sidebar just says so — no dashboard, no invite form, nothing to click:

![Sidebar showing "Coach application pending"](/docs/coaching-sidebar-pending.png)

If you're turned down, you can apply again any time — there's no cooldown and no need to ask an admin to reset anything first.

## How applications get reviewed

Admins see every pending application in one place, full qualification text included — this is the one thing that actually has to be read properly before deciding:

![Admin coach-applications review queue, showing an applicant's full details](/docs/coaching-admin-review-queue.png)

Approve or reject, with an optional note. Both decisions — and who made them, and when — stick around in a permanent history below the queue, including anyone who was approved by direct grant instead of a formal application:

![Decided applications, showing status and reviewer notes](/docs/coaching-admin-history.png)

For someone an admin already knows and trusts personally — no need to make them fill in a form — there's a direct-grant control on that user's admin profile page instead:

![Coach Status card on a user's admin page, before granting](/docs/coaching-admin-grant-before.png)
![The same card after granting coach status directly](/docs/coaching-admin-grant-after.png)

## Once you're approved

Settings confirms it, with a link straight through:

![Settings showing "You're an approved coach"](/docs/coaching-settings-approved.png)

And the coach dashboard is where you actually invite riders and see who's linked:

![The coach dashboard — invite form and rider roster](/docs/coaching-dashboard.png)

Invite by email. The rider needs an existing account already — this doesn't create one for them — and if they're under 16, their parent or guardian gets a consent request before the link goes active, the same as at sign-up. You can re-invite someone who declined or was removed at any time, no waiting period either way.

---

## What a coach can (and can't) see

Once a link is active:

- **Onboarding profile** — view only. If something looks wrong (height, rider level, whatever), you can flag it, which drops a note into the shared thread. You can't edit it directly — only the rider (or their parent/guardian) can.
- **Training goals** — read only, same idea.
- **A shared message thread** — for you and the rider only. It never includes the rider's private session notes.
- **Reports** — only what the rider actively sends you, from a session or the analytics page's "Send to Coach" button. Nothing is pushed automatically, and nothing appears in your dashboard until they do that. Unread ones are marked as such until you open them.

---

## Ending the relationship

Either side can end it, any time, with no cascade — it only removes the link, never any underlying data. A rider does this from Settings; a coach does it from the rider's card on their dashboard ("Remove trainee"). Admins can also force-revoke a link from a user's admin profile page, for safeguarding oversight.
